# rate-net v2.0.1 — docs.rs build fix

A patch release that fixes the documentation build on docs.rs. `2.0.0`'s docs.rs build failed because the crate marks feature-gated items with `doc(cfg(...))` badges without enabling the `doc_cfg` feature that docs.rs's nightly needs. No code, API, or behaviour changes: if `2.0.0` builds for you, `2.0.1` is identical apart from its documentation.

## Fixed

- **The docs.rs build failed** (`error[E0658]: the doc(cfg) and doc(auto_cfg) attributes are experimental`, nightly 1.101.0 2026-10-18). The crate root now enables `feature(doc_cfg)` under `cfg(docsrs)`, which only docs.rs sets, so stable and MSRV builds are unaffected.
- **CI now builds the docs exactly as docs.rs does** — nightly, `--cfg docsrs`, every feature (as `[package.metadata.docs.rs]` asks), and docs.rs's default target `x86_64-unknown-linux-gnu`, with rustdoc warnings denied — so a docs.rs failure shows up before a release instead of after it.

## Known issues

Unchanged from `2.0.0`:

- **Inserting a new key into a full store costs ~58 ns more than in 1.1.0** (≈293 → 351 ns at the default 1,048,576-key cap; measured on a loaded Windows host, best of runs, so approximate), because eviction checks that each candidate has fully recovered before evicting it — the price of never resetting a still-limited key. Checks of keys already tracked are unaffected, and below the cap nothing changes. A blocker for the next minor release, 2.1.0.
- **Past about twice the cap of still-limited evictions, `Overflow::FailClosed` (the default) denies some keys that owed nothing**; size the cap, alert on `recovery_load()` and `keys_refused`, or opt into `Overflow::Forget`. See the `2.0.0` notes and the README's "Sizing the cap".
