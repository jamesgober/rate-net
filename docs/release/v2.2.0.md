# rate-net v2.2.0

Fixes from an independent review. Upgrade recommended for limiters that use
`quota_for` with quotas of different speeds, the sliding-window log, or the
leaky bucket.

## What changed

- **Overflow charges stay within a key's own quota.** Debts spilled by keys
  under a slow per-key quota no longer lock newcomers under faster quotas out
  for the slow quota's recovery time. Sketch cells carry a quota class, a
  restored debt is cut to the key's own recovery time, and keys the sketch
  already covers can be evicted instead of filling the shard.
- **Sliding-window log memory is capped** on every construction path, at
  most 1 MiB per key.
- **Exact GCRA spacing.** The leaky bucket no longer admits a unit more than
  the burst across an interval boundary.
- **`Key::client_ip`**: per IPv4 address, per IPv6 `/64`. The plain
  `From<IpAddr>` conversion keys each address separately.
- **Docs:** what a `FailClosed` lockout costs an attacker and how to size the
  cap for slow quotas; per-algorithm memory; fail-closed `Decision` match
  examples.

## Behaviour changes

- The `GcraParams` word is in finer units; treat it as opaque. A word saved
  by 2.1 reads as a fuller bucket under 2.2.
- Under `FailClosed`, some floods that used to refuse newcomers
  (`keys_refused`) now charge them from the sketch (`keys_restored`). Both
  deny; the retry time is the newcomer's own.

## Compatibility

No public item removed or changed. MSRV stays at Rust 1.85.

## Upgrade

```toml
[dependencies]
rate-net = "2.2"
```
