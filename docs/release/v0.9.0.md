# rate-net v0.9.0 — Beta

**The surface is frozen, the threads are proven, and the compiler enforces it.** v0.9.0 starts the beta: only bug fixes and documentation polish remain before `1.0`. This release widens concurrency coverage to every algorithm and locks the thread-safety guarantees in at the *type* level so any future regression surfaces at compile time, not as a runtime failure.

## What is rate-net?

A powerful, lock-free rate limiter for Rust. It answers one question as fast as the hardware allows — *"is this key allowed right now?"* — and returns a decision plus a `retry-after`, tracking an independent allowance per key. Five algorithms behind one `Limiter` trait, per-key state in a sharded store bounded by eviction, hardened against adversarial traffic, with a frozen public API validated against a representative gatekeeper consumer.

## What's new in 0.9.0

### Concurrency proof for every algorithm

[`tests/stress.rs`](https://github.com/jamesgober/rate-net/blob/main/tests/stress.rs) now exercises every algorithm under real contention: with the clock frozen, eight threads hammer a single hot key against the token bucket, the leaky bucket, the fixed window, the sliding-window log, and the sliding-window counter. Each admits **exactly** its quota — proof the lock-free CAS paths (token / leaky / fixed) **and** the per-key `Mutex` paths (sliding-log / sliding-counter) are both correct under load. No over-admit, no lost decrement, no deadlock.

### `Send + Sync + 'static` at compile time

The public surface is shared across threads, and that promise is now type-checked. A compile-time assertion locks it in for every public type:

```rust
fn assert<T: Send + Sync + 'static>() {}

assert::<rate_net::RateLimiter>();
assert::<rate_net::AsyncLimiter>();      // under the `async` feature
assert::<rate_net::Decision>();
assert::<rate_net::Quota>();
assert::<rate_net::Eviction>();
assert::<rate_net::Algorithm>();
assert::<rate_net::RateLimiterError>();
assert::<rate_net::Key>();
```

Any regression that accidentally drops `Send` or `Sync` from a public type now fails the build, not a test run.

### Beta declaration

From here to `1.0`: bug fixes and documentation polish only. No API changes, no new features. Consumers can pin `rate-net = "0.9"` for the beta and upgrade to `1.0` without source changes.

## Breaking changes

None. No public items were added or changed.

All green.
