# rate-net v0.1.0 — Scaffold

**The first tag: structure, tooling, and quality gates — no limiter logic yet.** v0.1.0 establishes the crate metadata, the dependency wiring, the strict lint gate, and the documented shape of the API that lands across the `0.x` series. It compiles clean and green across the full CI matrix — Linux, macOS, and Windows on both stable and the 1.85 MSRV — with the `loom` model harness, the Criterion benchmark harness, `cargo audit`, and `cargo deny` all wired and passing. There are zero breaking changes because there is no prior release; the foundation API arrives in `v0.2.0`.

## What is rate-net?

A powerful, lock-free rate limiter for Rust. It answers one question as fast as the hardware allows — *"is this key allowed right now?"* — and returns a decision plus a `retry-after`, across multiple algorithms (token bucket, leaky bucket, fixed window, sliding-window log, sliding-window counter), while tracking per-key state in a sharded concurrent map so unrelated keys never contend. Memory is bounded by eviction, so a flood of unique keys hits a cap instead of growing without limit. rate-net does not reimplement token-bucket math; it consumes [`better-bucket`](https://crates.io/crates/better-bucket) for that and reads time from [`clock-lib`](https://crates.io/crates/clock-lib), then adds the per-key, multi-algorithm, retry-after machinery around them. It is the anchor crate of the `-net` domain group.

## What's in 0.1.0

### Crate root and the `VERSION` constant

`src/lib.rs` carries the crate-level documentation (the target API, the design goals, and the feature table) and the strict lint gate every later phase inherits: `deny(warnings)`, `deny(missing_docs)`, `deny(unsafe_op_in_unsafe_fn)`, and the `clippy` denies on `unwrap`/`expect`/`todo`/`unimplemented`/`print`/`dbg`/`unreachable`. The one callable item is the `VERSION` constant, resolved from `Cargo.toml` at compile time, with a unit test asserting it is well-formed `major.minor.patch` SemVer.

```rust
// Report the linked build at startup.
println!("rate-net {}", rate_net::VERSION);
```

### Dependency wiring and feature flags

The core dependencies are declared with `default-features = false`: `better-bucket` for token-bucket accounting and `clock-lib` for monotonic, mockable time. The sharded per-key store (`dashmap`) is an optional dependency pulled in by the default `std` feature, which keeps the crate `no_std`-capable — with `std` off the crate compiles down to just the `VERSION` constant, and the pared-down single-key mode follows in a later release.

| Feature | Default | Description |
|---------|---------|-------------|
| `std`        | yes | Standard library. Enables `dashmap` for the sharded store and eviction. |
| `algorithms` | no  | The full algorithm suite beyond the default token bucket. |
| `async`      | no  | Optional additive async-friendly wrapper. Implies `std`. |

### Benchmark and concurrency harnesses

Both harnesses the later phases depend on are in place and exercised from day one rather than bolted on later:

- `benches/rate_bench.rs` — a Criterion harness. With no `check` path to measure yet, the scaffold benchmarks the one step the limiter performs on every request before it touches a bucket: hashing the key and folding the digest down to a shard index. On the reference machine `locate_shard/single_key` measures ≈ 6.3 ns, an honest floor for the per-request work rate-net owns. The full single-key, many-key (shard scaling), contended, and eviction-sweep benchmarks land with the sharded core.
- `tests/loom_check.rs` — a `loom` model, gated on `cfg(loom)`. It proves the harness runs against this crate's toolchain and that the compare-and-swap contention kernel the per-key admit path will use never over-admits a key under any thread interleaving. The full per-algorithm no-over-admit proof replaces it in `v0.3.0`.

### CI and supply-chain gates

The `.github/workflows/ci.yml` matrix runs format, `clippy -D warnings`, test, and rustdoc (`-D warnings`) on Linux/macOS/Windows × stable + 1.85, plus a dedicated `loom` job and a security job running `cargo audit` and `cargo deny check`. The `deny.toml` policy allows the MIT / Apache-2.0 license family and standard permissive licenses, denies wildcard versions and unknown registries, and denies yanked crates.

**None.** This is the initial release.

## Verification

Run on Windows x86_64 (Rust stable 1.95.x and the 1.85 MSRV toolchain); the same commands pass on Linux (WSL2 Ubuntu) and across the configured CI matrix:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo build --no-default-features            # no_std build
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
RUSTFLAGS="--cfg loom" cargo test --test loom_check
cargo bench --bench rate_bench
cargo audit
cargo deny check
```

All green. Counts at this tag:

- Default features and `--all-features`: 1 unit test + 1 rustdoc test.
- Under `--cfg loom`: 1 concurrency model test.

## What's next

- **0.2.0 — Foundation.** Lock the public shape before implementing: the `RateLimiter` trait, the `Decision` result (`Allow` / `Deny { retry_after }`, `#[non_exhaustive]`), the quota and error types, clock-source injection, the Tier-1 entry points (`per_second`, `check`, `check_n`) backed by a simple correct implementation, and the per-algorithm over-admit invariant written as a `proptest`.
- **0.3.0 — Core.** The real sharded, lock-free, bounded-memory machine: the per-key store, the token-bucket algorithm wired to `better-bucket`, incremental LRU/TTL eviction, and the `loom` + eviction-under-load proofs.
