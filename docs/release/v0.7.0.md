# rate-net v0.7.0 — Hardening + API freeze

**Tested against the threat model, and the surface is now fixed.** v0.7.0 throws hostile traffic at the limiter — unique-key floods, burst storms, clock jumps, no time advance, near-maximum requests, rapid reconfiguration — and proves the invariants hold: no panic, no wrap, never over-admit, memory stays bounded. With that confidence, the public API is frozen: it will not change before `1.0`.

## What is rate-net?

A powerful, lock-free rate limiter for Rust. It answers one question as fast as the hardware allows — *"is this key allowed right now?"* — and returns a decision plus a `retry-after`, tracking an independent allowance per key. Five algorithms behind one `Limiter` trait, per-key state in a sharded store bounded by eviction, token-bucket accounting delegated to [`better-bucket`](https://crates.io/crates/better-bucket).

## What's new in 0.7.0

### Adversarial-traffic hardening

A new suite ([`tests/hardening.rs`](https://github.com/jamesgober/rate-net/blob/main/tests/hardening.rs), 15 tests) is built around the threat model — that every key is hostile until proven otherwise — and asserts no panic, no wrap, no over-admit, and bounded memory under:

- **A flood of 100 000 unique keys** — the live-key count stays within the capacity bound, and a key kept warm throughout is never corrupted (it still enforces and refills its own limit afterward).
- **A burst storm** of ten times the quota fired at one instant — exactly the quota is admitted.
- **No clock advance** — exactly the quota is admitted, no more.
- **A 100-day clock jump** — the bucket refills to its cap and never beyond; the millisecond counter wraps safely.
- **A request of `u32::MAX` units** — denied with `Duration::MAX`, no panic, and the limiter remains usable.
- **A `u32::MAX` quota and a zero quota** — neither panics.
- **Rapid reconfiguration** — `with_shards` / `with_eviction` chained repeatedly.

### Per-algorithm edge matrix

The same suite walks every algorithm (token bucket, leaky bucket, fixed window, sliding-window log, sliding-window counter) through its edges: zero-unit checks always admit, exactly the quota is admitted in a window, a request larger than the quota is permanently refused, the allowance refills after enough time, and the exact window boundary is handled. One subtlety surfaced and is documented: the sliding-window counter weights the just-ended window fully *at* the boundary, so it refills gradually rather than all at once — correct behaviour, now covered by a test.

### API freeze

The public surface is fixed: `RateLimiter` and its methods, `Builder`, `AsyncLimiter`, `Limiter`, `Decision`, `Quota`, `Eviction`, `Algorithm`, `RateLimiterError`, `Key`, and `VERSION`. Nothing will be removed or have its signature changed before `1.0`; any additions will be additive and backward-compatible. Consumers can build against `0.7` and upgrade through the `0.x` line without breakage.

## Breaking changes

None — and by design, none from here to `1.0`.

## Verification

Run on Windows x86_64 (Rust stable 1.95.x and the 1.85 MSRV toolchain); the same commands pass on Linux (WSL2 Ubuntu), and macOS is covered by the CI matrix:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets -- -D warnings
cargo test --all-features
cargo test
cargo build --no-default-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps
RUSTFLAGS="--cfg loom" cargo test --test loom_check
cargo audit
cargo deny check
```

All green. Counts at this tag:

- `--all-features`: 78 unit + 54 rustdoc + 6 property + 1 stress + 1 allocation-audit + 15 hardening tests.
- Default features: 53 unit + rustdoc + 2 property + stress + allocation-audit + the (token-bucket subset of) hardening tests.
- Under `--cfg loom`: 2 concurrency model tests.

## What's next

- **0.8.x — Alpha.** Integrate against a real consumer (a gatekeeper such as `bouncer-io`) through the public API only, confirming the allow/deny boundary holds.
- **0.9.x — Beta → RC.** Bug-fix-only stabilization and the soak.
- A faster monotonic clock in `clock-lib` (raised separately) remains the path to beating `governor` on raw latency.
