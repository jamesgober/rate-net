# rate-net v0.6.0 — Optimization

**Less work per check, and an honest scoreboard.** v0.6.0 profiles and tightens the hot path — faster hashing and, on the default path, no clock read at all — cutting the steady-state check from ~77 ns to ~54 ns. It also lands a head-to-head benchmark against `governor` and records the result truthfully, blocker and all. No new features; no breaking changes.

## What is rate-net?

A powerful, lock-free rate limiter for Rust. It answers one question as fast as the hardware allows — *"is this key allowed right now?"* — and returns a decision plus a `retry-after`, tracking an independent allowance per key. Five algorithms behind one `Limiter` trait, per-key state in a sharded store bounded by eviction, token-bucket accounting delegated to [`better-bucket`](https://crates.io/crates/better-bucket), time from [`clock-lib`](https://crates.io/crates/clock-lib).

## What changed in 0.6.0

### Faster hashing

Shard selection and the per-key shard map now hash with [`ahash`](https://crates.io/crates/ahash) instead of SipHash. It is several times faster on short keys, and a random per-store seed keeps it collision-attack resistant against hostile keys.

### No redundant clock read on the hot path

The biggest win. The token bucket already reads the monotonic clock once (inside `better-bucket`, for refill). v0.5 read it a *second* time in rate-net to stamp the key's "last seen" time for eviction. v0.6 removes that second read on the default path: least-recently-seen eviction now orders by a cheap per-shard logical counter, and the real clock is read only when a window algorithm or an idle TTL genuinely needs wall time.

### Inlined check path

`#[inline]` on `check` / `check_n` and the internal dispatch, so the path inlines across the crate boundary for callers building without LTO.

### Results

Criterion means on Windows x86_64 (Rust stable, `opt-level = 3`):

| Path | v0.5.0 | v0.6.0 | Change |
|------|-------:|-------:|-------:|
| Single-key check | ~77 ns | ~54 ns | −30% |
| Many-key check (64 shards) | ~99 ns | ~54 ns | −45% |
| Contended single key (4 threads) | ~76 ns/op | ~54 ns/op | −29% |
| Eviction sweep | ~287 ns | ~217 ns | −24% |

### Head-to-head vs `governor` — recorded honestly

A new comparison bench ([`benches/comparison.rs`](https://github.com/jamesgober/rate-net/blob/main/benches/comparison.rs), gated on `cfg(comparison)` so it never enters the default tree or CI) pits rate-net against `governor`:

| Path | rate-net | governor |
|------|---------:|---------:|
| single key | ~44 ns | ~17 ns |
| many keys | ~54 ns | ~18 ns |

**`governor` is currently faster, and v0.6 does not hide it.** The gap is almost entirely the clock: `governor` reads a TSC-based [`quanta`](https://crates.io/crates/quanta) clock (~5 ns) by default, while rate-net reads `std::time::Instant::now()` (~20 ns on Windows) through `better-bucket` → `clock-lib`. That difference, paid on every check, accounts for the bulk of it; the rest is rate-net's sharded-store layering over `better-bucket` versus `governor`'s tightly-integrated GCRA. rate-net's *own* per-key overhead is competitive once the clock is held equal — but the clock lives in sibling crates (`clock-lib` / `better-bucket`), not here, and beating `governor` end-to-end needs a fast TSC/`quanta`-style monotonic source there. That is tracked as a separate sibling enhancement. The full analysis is in [`docs/BENCHMARKS.md`](https://github.com/jamesgober/rate-net/blob/main/docs/BENCHMARKS.md).

### Doc-build hardening

A `cargo doc` on the **default** feature set is now part of CI — a feature-gated item (`AsyncLimiter`) had slipped a broken intra-doc link into the always-compiled crate docs, which only `--all-features` doc builds had been catching.

## Breaking changes

None. The `ahash` dependency is internal; the public API is unchanged.

## Verification

Run on Windows x86_64 (Rust stable 1.95.x and the 1.85 MSRV toolchain); the same commands pass on Linux (WSL2 Ubuntu) and across CI:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets -- -D warnings
cargo test --all-features
cargo test
cargo build --no-default-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps                 # default features too
RUSTFLAGS="--cfg loom" cargo test --test loom_check
cargo bench --bench rate_bench
RUSTFLAGS="--cfg comparison" cargo bench --bench comparison    # vs governor
cargo audit
cargo deny check
```

All green. Counts unchanged from `0.5.0`: `--all-features` 78 unit + 54 rustdoc + 6 property + 1 stress + 1 allocation-audit; default 53 unit + rustdoc + 2 property + stress + allocation-audit; `--cfg loom` 2 model tests.

## What's next

- **0.7.0 — Hardening + API freeze.** Adversarial-traffic and edge-matrix testing across all platforms (unique-key floods, burst storms, clock-jump, near-max `n`, rapid reconfiguration), and the API freeze.
- A faster monotonic clock in `clock-lib` (raised separately) is the path to beating `governor`.

```toml
[dependencies]

rate-net = { version = "0.6", features = ["algorithms", "async"] }
```
