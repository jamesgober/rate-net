# rate-net v0.8.0 — Alpha

**The first real consumer drives the surface.** v0.8.0 is the alpha: a representative gatekeeper — the shape `bouncer-io` will take — integrates with rate-net through the public allow/deny API only, confirming the boundary holds. It read naturally and needed no API additions, so the frozen surface is confirmed consumable.

## What is rate-net?

A powerful, lock-free rate limiter for Rust. It answers one question as fast as the hardware allows — *"is this key allowed right now?"* — and returns a decision plus a `retry-after`, tracking an independent allowance per key. Five algorithms behind one `Limiter` trait, per-key state in a sharded store bounded by eviction, hardened against adversarial traffic, with a frozen public API.

## What's new in 0.8.0

### First-consumer shake-out

A new integration ([`tests/consumer_pattern.rs`](https://github.com/jamesgober/rate-net/blob/main/tests/consumer_pattern.rs)) exercises the surface the way a gatekeeper such as `bouncer-io` will:

- It codes against the **`Limiter` trait**, not the concrete type — so a consumer never names the limiter's clock or internals.
- It keys by **caller identity** (IP and user) and turns a `Decision` into its own HTTP-shaped verdict (`200` / `429` + `Retry-After`).
- It holds the limiter behind an **`Arc`** and shares it **across threads**, exactly as a server would; per-client limits stay exact under contention.
- It works unchanged across **every configured algorithm** and with the **async** await-until-ready wrapper (a queueing gatekeeper).
- It touches **only the public API** — the "consumers call the API, never touch internal state" boundary is enforced by visibility and demonstrated here.

```rust
use rate_net::{Decision, Limiter, RateLimiter};

// A gatekeeper's admission check, generic over any limiter.
fn admit<L: Limiter>(limiter: &L, key: &str) -> u16 {
    match limiter.check(key) {
        Decision::Allow => 200,
        Decision::Deny { .. } => 429,
        _ => 429,
    }
}

let limiter = RateLimiter::per_second(100);
assert_eq!(admit(&limiter, "client:7"), 200);
```

### Runnable gatekeeper example

[`examples/gatekeeper.rs`](https://github.com/jamesgober/rate-net/blob/main/examples/gatekeeper.rs) is a minimal HTTP-style gatekeeper that limits per client IP and returns `429 Too Many Requests` with a `Retry-After`:

```text
cargo run --example gatekeeper
```

## A note on the `bouncer-io` wiring

The actual `bouncer-io` integration is a separate effort: rate-net is not yet published, and sibling crates are not edited from this repository. The representative gatekeeper here is faithful to that integration — same trait, same allow/deny boundary — and confirms rate-net is ready for it.

## Breaking changes

None. No public items were added or changed; the API remains frozen.

Run on Windows x86_64 (Rust stable 1.95.x and the 1.85 MSRV toolchain); the same commands pass on Linux (WSL2 Ubuntu), and macOS is covered by CI:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets -- -D warnings
cargo test --all-features
cargo test
cargo build --examples --all-features
cargo build --no-default-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps
RUSTFLAGS="--cfg loom" cargo test --test loom_check
cargo audit
cargo deny check
```

All green. The consumer-pattern integration adds 5 tests (`--all-features`).
